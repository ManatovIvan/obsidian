# Журнал отступлений и решений реализации (к предрегистрации 6GGC73ZD)

Предрегистрация утверждена 2026-10-12 и не меняется. Здесь записано всё, что при реализации
пришлось решить сверх неё, и всё, что пошло не по плану. Каждый пункт — с причиной.

## Решения реализации, которых нет в предрегистрации

1. **Валидация в S3** — последние 2/9 времени обучающих сессий (то же отношение 70:20, что в S1/S2).
   В §4 сказано только, какие сессии обучающие и тестовые.
2. **Дисбаланс классов в M1** — в каждой эпохе класс-большинство случайно прореживается до
   размера меньшего класса. Причина: в E1 кадров ESP32 в 18 раз больше, чем роутера. На AUC
   (метрика без порога) это прямо не влияет, но меняет то, на чём учится сеть.
3. **M1, детали, не названные в статье M8AF4MW7** — свёртки без дополнения; dropout 0,5 после
   слоя 256. **M2** — дополнение 'same' (иначе выход не совпадает со входом по размеру).
4. **Остановка обучения M2** — по MSE на валидации (у автоэнкодера нет точности, а у Yu et al.
   критерий — точность).
5. **Предохранитель** — в первых двух запусках стояло «не более 200 эпох» без источника (см. п.12).
6. **Одно зерно** (20260504) для всего: разбиения, инициализации, бутстрэпа. Разброс из-за
   случайности обучения не оценивается — это ограничение.
7. **H2 и H3** — §5.4 не называет вариант (C2 — SNR, C4 — CFO). Решение выводится для каждого
   из 4 вариантов отдельно, ничего не выбирается задним числом.
8. **Шум (C2)** — блоки по 100 мкс, отступ 1 мс от любого найденного кадра, 20 000 случайных
   блоков на сессию, медиана. Для кадров без MPDU занятым считается интервал 200 мкс после SFD.

## Результаты проверок, определившие ход работы

9. **C3** — скремблированные биты окна у роутера и обеих плат ESP32 совпали (out/dataset_report.txt).

## Сбои и исправления

10. **Тип данных в M2** — тест test_minmax_maps_training_data_to_unit_interval обнаружил, что
    to_tensor_m2 возвращал float64 при входе complex128 (это бывает после снятия CFO). Модель
    работает во float32, поэтому варианты M2 со снятым CFO упали бы. Исправлено до того, как
    такой вариант был посчитан: теперь всё во float32. Для уже посчитанных вариантов (вход
    complex64) результат не меняется.
11. **Скорость против побитовой повторяемости** — первый запуск шёл в детерминированном режиме
    cuDNN; M2 обучался 36,5 с на эпоху и за 45 мин не дошёл до остановки (оценка всего прогона —
    десятки часов). Замер на тех же данных: без детерминированного режима — 12,9 с на эпоху.
    Прогон остановлен и запущен заново с нуля в недетерминированном режиме, включая уже
    посчитанные строки (S1: M3 и M1 дали AUC 1,000) — чтобы все результаты были получены
    одинаково. Математика модели и зёрна не изменились; повторный запуск может отличаться
    в последних знаках из-за порядка сложения на GPU.
12. **Правило завершения обучения по Prechelt (решение автора 2026-10-12: «Переделываем по Prechelt»)** —
    во втором запуске M2 обучался 144 эпохи без остановки: правило Yu (10 эпох без улучшения на
    валидации) не срабатывало из-за редких крошечных улучшений, и запуск упёрся бы в мой
    предохранитель 200 эпох, у которого нет источника. Минимального порога улучшения не нашлось
    ни в одном источнике (Yu; DeepCRF — «patience value of 10»; NFC — «tolerance … 6»). Добавлено
    правило завершения из Prechelt 1998 (UP4AH8PI): обучение останавливается также, когда прогресс
    обучения P₅ (по полосам из 5 эпох) ниже 0,1 ‰, и не позже 3000 эпох; ошибка обучения — средняя
    по всей обучающей выборке после эпохи, как у Prechelt. Правило Yu сохранено. Второй запуск
    остановлен и сохранён в out/aborted_run2/, прогон начат заново с нуля.
13. **Правило остановки для мини-батчевого обучения (решение автора 2026-10-12: «Давай B, если это
    будет честный академический метод»)** — правило Prechelt (п.12) подобрано для обучения на полном
    наборе (у Prechelt — RPROP), а у нас Adam с мини-батчами по 64 (Yu). Принято стандартное решение
    для мини-батчей: новый минимум ошибки на валидации принимается, только если он значим
    (Bengio 2012, M6RCP432, с.10, сноска 16); порог значимости — относительное улучшение не менее
    0,5 % (improvement_threshold = 0.995 из Deep Learning Tutorials, V5RD886G, на которые ссылается
    Bengio). Терпение Yu (10 эпох) сбрасывает только значимое улучшение; лучшие веса сохраняются при
    любом улучшении. Ошибка на валидации: M1 — доля неверных ответов (zero-one loss, как в Tutorials),
    M2 — MSE. Правило прогресса Prechelt убрано; от Prechelt оставлен только предел 3000 эпох как
    страховка. Оговорка: 0,995 — значение из учебного кода, а не результат исследования порога.
    Честность смены правила: все три смены (п.11–13) вызваны временем обучения, а не результатами;
    остановка использует только валидационную выборку; к моменту смены тестовые результаты были
    только у S1 (M3 и M1 без контролей, AUC 1,000), по M2 и по контролируемым вариантам M1 тестовых
    чисел не было. Запуск 3 сохранён в out/aborted_run3/, прогон начат заново с нуля.
14. **Сбой инструмента ссылок (не влияет на методику и результаты)** — первая версия citation_links.py
    при повторном запуске удаляла старую ссылку жадным шаблоном и вместе с ней символы, стоявшие сразу
    после «⟧» (кавычки докстрингов, запятые, точки). Три модуля перестали компилироваться. Восстановлено:
    dsss_rx.py, iq_io.py, mac80211.py, test_dsss_rx.py, analyze_labels.py — из эталонов (резервная копия и
    тексты в Zotero), models.py, metrics.py, dataset_build.py — сверкой каждого места с написанным текстом.
    Логика кода проверена сравнением синтаксических деревьев и тестами (20 из 20); check_citations —
    134 OK. Шаблон ссылки сделан точным, повторный запуск проверен на неизменность файлов.
    Идущий прогон экспериментов не затронут: код был загружен до сбоя.
